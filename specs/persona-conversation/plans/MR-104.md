reply, end it, show the AI-recreation notice, and keep an audit row per turn with IDs and timings but no text.

MR-105 swaps it in. Membership (`personmember`, MR-110-ish) does not exist yet, so "owner or member" is
owner-only today; `get_person_for_conversation` in `routes/persons.py` is already the single seam for that.

## Design
**Models**
- `Conversation`: `id`, `person_id`, `user_id`, `status` (open|ended, VARCHAR), `created_at`, `last_message_at`, `ended_at`.
- `ConversationMessage`: `id`, `conversation_id`, `role` (user|persona), `content` Text, `created_at`. Ordered by `created_at, id`.
- `PersonaTurn`: `id`, `conversation_id`, `item_ids` JSON (list of extracted-memory ids, ids only), `fallback` bool, `first_token_ms`, `total_ms`, `created_at`. No text columns (NFR-3).
- Relationships with `cascade_delete=True` on `User.persons` already exist; person → conversations needs a `Person.conversations` relationship or DB-level CASCADE (DB-level is enough, same as `memory.person_id`'s comment: the FK does it, no ORM relationship needed).

**Endpoints** (`router = APIRouter(tags=["conversations"])`, full paths per the ticket)
1. `POST /persons/{person_id}/conversations` → `ConversationOpened`. `get_person_for_conversation` (404 / 403). Creates the row and the first message (`role=persona`, content `PERSONA_NOTICE`). Superuser who isn't owner gets 403 (AC-4.4, 4.6).
2. `POST /conversations/{id}/messages` → `StreamingResponse(media_type="text/event-stream")`.
   - Before streaming (sync, in the request session): load conversation (404), `conversation.user_id != current_user.id` → 403 (AC-4.5; superuser no exception), `status == ended` → 409 "Conversation has ended", re-check access to the person via `get_person_for_conversation` (a later revoke must stop it). Read `history` (all stored messages), insert the user message, bump `last_message_at`, commit, then read what the generator needs (person id/name, history list) into plain values and close the request session's transaction.
   - Generator opens its **own** `Session(engine)` (the request-scoped session may close before a streaming body finishes; and `reply` must not hold a read transaction while the model streams, as in `search_persona`). Emits `event: token\ndata: {"text": ...}` per `TokenEvent`; on `DoneEvent` stores the persona message (full text joined from tokens), writes one `PersonaTurn`, then emits `event: done` with `DoneEvent` fields plus `notice=PERSONA_NOTICE` (AC-7.2). On `LLMError` or any other exception: log id/turn/exception type only, emit `event: error\ndata: {"detail": "The AI service is unavailable."}` (generic; reuse `LLMError`'s message only when it is an `LLMError`, which is already generic). Nothing is stored for a failed reply; the user message stays so a retry has the history.
   - Timings with `time.perf_counter()`: `first_token_ms` at the first `TokenEvent`, `total_ms` at the end.
3. `POST /conversations/{id}/end` → `Message`/small schema. Same 404/403 checks. Calls `end_conversation_summary(...)` only if it exists (MR-106 absent → skip, with a one-line comment), sets `status=ended`, `ended_at`, deletes the messages. Ending an already-ended conversation is idempotent (200).

**Stub `reply`** in `persona_events.py`, signature exactly as agreed (with `person_name`, optional `summary` per DEV-1):
```python
def reply(session, llm, *, person_id, person_name, history, message, summary=None) -> Iterator[PersonaEvent]
```
yields `TokenEvent(PERSONA_NO_MEMORY)` then `DoneEvent(sources=[], fallback=True, notice=PERSONA_NOTICE)`. The route imports it as `from app.services import persona_events`; MR-105 only changes the import/call target.

**Prompt text (needs your OK, wording is user-facing)**
- `PERSONA_NOTICE`: "You are talking with an AI recreation built from your family's memories. It is not the real person and can be wrong." A fixed constant with no placeholders (tests compare it byte for byte).
- `PERSONA_NO_MEMORY`: "I don't remember that. It isn't in the memories my family shared."

**Logging (AC-N3.1):** `logger.info("persona turn", extra=...)`-style lines with conversation id, turn number, source count, `first_token_ms`, `total_ms`. Never text, names or detail strings from exceptions.

**Privacy/AI rules checked:** answers only from confirmed memories (MR-105's job; the stub makes no model call); no hosted AI; no real uploads touched; no memory text in logs or errors.

## Risks
- **Session lifetime while streaming** — handled by the generator's own session.
- **Client disconnect mid-stream** — generator is closed by Starlette; nothing is written until `DoneEvent`, so no half reply is stored.
- **Migration head** — confirm a single head after rebasing on `main`.
- **Interface drift with MR-105** — kept to the agreed signature; any change goes through the ticket's Questions.
- **Size** — expect ~450 changed lines excluding client and migration; if it runs over, split tests for delete paths into a follow-up.
