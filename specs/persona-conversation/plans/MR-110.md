## Design
- **Open:** `useQuery` keyed `["conversation", personId]` calling `ConversationsService.openConversation` (`staleTime: Infinity`, `gcTime: 0`, no refetch on focus or mount, `retry: false`), so React StrictMode's double mount opens **one** conversation and leaving the page drops it (the idle sweep ends abandoned ones). The query function **turns a 403 or 404 into data** (`denied` / `notFound`) because the app's global error handler logs the user out and redirects to `/login` on any 401/403 from the generated client; a revoked member must see "you no longer have access", not be logged out. The cache holds only the conversation id and the notice, never message text.
- **Notice:** shown in a `role="note"` block above the scrolling list so it stays visible (AC-13.1).
- **Messages:** a list with `role="log"`, `aria-live="polite"`, label "Conversation". A sent message appears at once (AC-13.2); the persona's message is added empty and grows token by token; the input and Send are disabled until `done` or `error`.
- **Stream:** `streamMessage` POSTs `{text}` with the same bearer token the generated client uses (`localStorage.access_token`) and the client's `baseURL`, reads the body, splits on blank lines, parses `event:` / `data:`. Non-2xx throws `ChatStreamError` with the status; it does not go through axios, so the global logout handler is not triggered.
- **After `done`:** each `[n]` with `1 ≤ n ≤ sources.length` becomes a link that focuses the matching entry in the **Sources** list (`<ol aria-label="Sources">`, item text + memory title); any other `[n]` stays plain text (AC-13.3). `fallback` → ordinary reply, no sources. `uncited && !fallback` → small note "This reply is not backed by a memory." (AC-13.4).
- **Errors:** an `error` event or network failure removes the unfinished reply, shows `role="alert"` "Something went wrong. Please try again." (never server text), and puts the typed text back in the input (AC-13.5). 403 → "You no longer have access to this conversation." and 409 → "This conversation has ended." with sending disabled (AC-13.7).
- **End:** a confirm dialog says the chat will be deleted and a short note kept; confirming calls `ConversationsService.endConversation`, then navigates to `/persons` (AC-13.6).
- **Form:** `react-hook-form` + `zod` (`text` 1..2000, schema above the component), `LoadingButton`, `Textarea`, `FormLabel` "Your message" (`sr-only`), per `code-style.md`. Enter sends, Shift+Enter adds a line.
- **NFR-8:** no message, reply, source or summary text in localStorage, sessionStorage, the URL, a persisted cache or any `console.*`. The header shows the person's name only when `readPerson` succeeds (owner); a member sees "Talk with the persona".
- Entry point: a "Talk" item in the people page's actions menu. A member's entry point arrives with MR-112/113.

## Tests (`frontend/tests/chat.spec.ts`, new user per file, backend with `AI_BACKEND=fake`)
Seed through the generated services (log in, create person, create a memory, link it, wait for the extracted items, confirm them) in `utils/persona.ts`.
- AC-13.1 *Notice stays visible*: open the chat, notice shown; send a message; notice still visible.
- AC-13.2 *Reply streams in*: the sent message appears at once; with a delayed intercepted response the input is disabled, then enabled; the log region has `aria-live="polite"`.
- AC-13.3 *Citations link to sources* (real fake backend: `Fake answer citing [1].` with the seeded item): `[1]` is a link, clicking it focuses the first source, whose text is the seeded fact; intercepted reply with `[1]` and `[9]`: `[9]` stays plain text.
- AC-13.4 *No-memory and uncited replies*: an unrelated question shows the fixed "I don't remember that…" reply with no Sources list; an intercepted uncited `done` shows the note.
- AC-13.5 *Errors keep the typed text*: intercepted `error` event and an aborted request: generic alert, input has the text back, no server text.
- AC-13.6 *End conversation*: confirm dialog text, confirming returns to People; the conversation is ended in the API.
- AC-13.7 *Access removed or ended*: intercepted 403 and 409: clear message, Send disabled.
- AC-N8.1 *Nothing stored in the browser*: after a chat, no localStorage or sessionStorage value contains the message or reply text, the URL has none, and no console message contains it.

## Risks and open points (go in the ticket's Questions)
1. **Q12 still pending** (above).
2. **The app logs the user out on any 403** from the generated client; the chat avoids it only for its own calls. A revoked member opening other pages is unaffected.
3. A failed turn leaves the user's message stored on the server (as designed in MR-104), so a retry sends it twice; the UI marks the unanswered message "Not answered".

5. Leaving the page abandons the conversation; the 30-minute idle sweep ends and summarizes it.
