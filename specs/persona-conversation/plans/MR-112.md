## Context
A member can talk with a persona but cannot learn the person's id or name: `GET /persons/` lists only the caller's own and
`GET /persons/{id}` is owner-only. This adds the one read the sharing screens (MR-113) need.

## Design
- Select `Person` joined to `PersonMember` where `PersonMember.user_id` is the caller. Read live, so a revoked member drops out at once.
- Response carries `id` and `name` only: no owner, no `other_names`, no memory data (memorial-privacy rule 2).
- The caller's own persons never appear (no member row for an owner). Superusers get no extra rows.
- Ordered by name, then id, so the list is stable.

## Tests
Member sees the person; only `id` and `name` come back; outsider and non-member superuser get an empty list; owner's own
persons are absent; a revoked member loses it; `shared` is not parsed as an id; no token is 401.
