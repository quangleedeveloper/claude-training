## Design
- **Offer:** a dialog with a textarea (`zod`: trimmed, 1 to 5000 characters, same as the API) that says the family decides. It calls `createOffer` and shows the API's own confirmation. Nothing is stored or logged in the browser. It is hidden once access is lost or the person is missing.
- **Inbox:** an "Offers" item in the people menu opens a dialog that loads `readOffers` only when opened (`gcTime: 0`). Accept calls `acceptOffer`, says the new memory "is not yet confirmed" and links to Memories, and invalidates `["memories"]`. Decline asks "Decline this offer?" inline, then calls `declineOffer`.
- **Members never see the list:** the people page lists only the caller's own persons, so a member has no menu, and the API answers 403 (tested).

## Deviations from the ticket
- "On the person's page": there is no person page, so the list is a dialog from the people menu. The accepted memory's link goes to the Memories list, because the memories page has no per-memory route.

## Tests (`tests/offers.spec.ts`, backend with `AI_BACKEND=fake`)
Member offers and is told the family decides; a blank offer is refused; the owner sees the offer with Accept and Decline; accepting shows the not-yet-confirmed note and the memory shows up; declining asks first and the offer is gone; a member has no menu and the API returns 403.
