# Plan: MR-118 Text editor for the Memory field

status: implemented on `feat/mr-118-rich-text-memory-editor`

ticket: tickets/MR-118.md · spec: none (UI only) · size S · demo: no.

## Decision (asked of the user)
Rich text, stored as Markdown in `content` (not HTML, not a bigger plain text area).

## Design
- `MemoryEditor` wraps Tiptap (`useEditor`, StarterKit, `@tiptap/markdown`). Value in and out is a Markdown string, so it plugs into `react-hook-form` like the text area did. Only toolbar formats are enabled (no link, code, strike, underline). The editor is a labelled `textbox`, and the toolbar buttons are labelled and show `aria-pressed`.
- The editor follows the form when the value changes from outside (reset after saving) without emitting an update.
- `markdownToPlainText` strips the few marks the editor writes, for the one-line table cell.
- No backend change: `content` is still a string of up to 5000 characters.
