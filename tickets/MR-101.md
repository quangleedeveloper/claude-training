## What to build
- `person` table and migration; `memory.person_id` (nullable, `ON DELETE SET NULL`, indexed).
- `persons.py` router: create, list, read, update (name, other names), delete. Owner only.
- `PUT /memories/{id}/person` to link or unlink one of the owner's memories.
- Access helper `get_person_for_conversation(session, user, person_id)` in `app/api/deps.py` or the router: 404 if missing, 403 unless owner. MR-107 widens it to members; keep it the single place that decides.

## Files
`app/models.py` (Person only), new migration, `app/api/routes/persons.py`, `app/api/routes/memories.py` (link endpoint), `app/api/main.py`, tests under `tests/api/routes/test_persons.py`. Stay inside these so tickets can run in parallel worktrees; if you need another file, ask below first.

## Notes
- AC-1.3 lists rows that later tickets add (conversations, summaries, members, offers, audit). Here, test that the person's memories stay and are unlinked; each later ticket adds its own delete test for its table.
- `person_name` on `Memory` stays; don't migrate or drop it (spec: Design notes).
