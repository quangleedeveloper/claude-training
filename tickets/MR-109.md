### QA → BA · 2026-10-28
**QA-1. Eval format needs fields for conversations.** Persona cases need earlier turns, a past summary, who is asking, and "must not cite". I proposed optional fields in `evals/grounding/README.md` (`person`, `as`, `turns_before`, `summary`, `expect.not_cites`, and a missing `fallback` meaning either). Please confirm before the runner is built.
> BA answer (BA, 2026-10-28): Confirmed as proposed (`person`, `as`, `turns_before`, `summary`, `expect.not_cites`, and a missing `fallback` meaning either). The README note now says confirmed.

**QA-2. AC-N2.1 can't run in CI.** It says "on the demo machine"; CI runners have different hardware. Proposed: CI reports latency for information only, and the pass/fail check is a manual run on the demo machine before the demo, posted in this ticket. Also still needed: the pass-rate threshold (ticket note).
> BA answer (BA, 2026-10-28): Agreed. AC-N2.1 is reworded: a manual run on the demo machine before the demo decides pass or fail, with the report posted in MR-103; CI shows latency for information only. The pass-rate threshold is now its own row in the spec's Areas of concern: BA proposes 90% plus zero invented memories, for the Lead and QA to agree.

### Dev → BA · 2026-10-28 (from plan mode)
**DEV-1. Definition of an invented memory.** Proposed: any `must_not_include` hit, or a cited source not in the case's fixture. The gate fails if the count is above 0.
> BA answer (BA, 2026-10-28): Accepted. The definition is now in AC-N7.1.

**DEV-2. Where the eval run happens.** GitHub runners have no GPU, and pulling `llama3.1` takes minutes. Proposed: a self-hosted runner labelled `ollama` on a team machine (synthetic data only). Alternative: install Ollama in the GitHub job and accept about 15 minutes per run.
> BA answer (BA, 2026-10-28): **Lead decided: a self-hosted runner** labelled `ollama`, synthetic data only. The static validator stays on GitHub's runners. Recorded in the spec's design notes.
