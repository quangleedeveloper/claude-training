## What to build
- A chat screen for one person, reached from a "Talk" action on the people page (`PersonActionsMenu`) and, for members, from MR-113's "Shared with me" list.
  - Opens a conversation (`POST /persons/{id}/conversations`) and shows the notice first and always.
  - Sends a message (`POST /conversations/{id}/messages`), shows it at once, and grows the reply as `token` events arrive; the input is disabled until `done` or `error`.
  - Shows `[n]` as a link to the matching entry in the **Sources** list under that reply (`done.sources`: item text and memory title); an `[n]` with no source stays plain text.
  - `done.fallback`: the fixed reply as an ordinary reply, no sources. `done.uncited`: a small "this reply is not backed by a memory" note.
  - `error` or a network failure: a generic message, the typed text kept for retry.
  - **End conversation**: confirm dialog (the chat is deleted, a short note of it is kept), then `POST /conversations/{id}/end` and back to the person.
  - 403 or 409 on send: a clear "you no longer have access" / "this conversation has ended" message and sending disabled.
- The streamed reply region is `aria-live="polite"`; the whole screen works by keyboard.

## Notes
- **Streaming from the browser.** The generated client cannot read `text/event-stream` and `EventSource` cannot POST, so `streamMessage.ts` uses `fetch` with a body stream reader and the same bearer token the generated client uses, and parses `event:` / `data:` blocks. Everything else (open, end) uses the generated `ConversationsService`.
- Follow `.claude/rules/code-style.md`: TanStack Query for server state, `useMutation` with `onError: handleError.bind(showErrorToast)`, `useCustomToast`, `cn()`, theme tokens, route `head` title "`Chat - Memorial Robot`", shadcn primitives from `components/ui/`.
- **NFR-8:** message text, replies, sources and summaries are never put in localStorage, sessionStorage, the URL, a persisted query cache, analytics or `console.*`. Add a Playwright check (storage empty of the message text, no console output containing it).
- The Playwright spec runs against the stack with `AI_BACKEND=fake` (as `confirm.spec.ts` does). Seed a person with a confirmed item through the API helpers in `frontend/tests/utils/`; the fake reply cites `[1]`.
- Never show raw server error text in the chat.

**DEV-1. Q12 is still pending.** Built at the user's request; the Lead's answer is not recorded. Please answer Q12 in `tickets/MR-100.md`, or tell us to hold this back.
**DEV-2. A 403 elsewhere logs the user out.** The app's global handler (`main.tsx`) removes the token and redirects to `/login` on any 401 or 403 from the generated client. The chat avoids it for its own calls (opening turns a 403 or 404 into a message; the reply stream uses `fetch`), so a revoked member sees "you no longer have access" and stays signed in. The handler itself is untouched; should a 403 really mean "log out"?
**DEV-3. Names for members.** Only the owner can read the person, so a member's chat says "Talk with the persona". Showing the name needs a member-safe endpoint (MR-112).
**DEV-4. Retrieval looks at the last two questions too** (AC-4.3), so a second question on another topic can still show the first answer's source. That is the backend's design, not a screen bug; the e2e asks the no-memory question first.
**DEV-5. A failed turn is sent twice on retry.** The server keeps the user's message of a failed turn (MR-104), so retrying stores it again; the screen marks the unanswered message "Not answered" and gives the text back.
**DEV-6. Leaving the page abandons the conversation.** The 30-minute idle sweep ends and summarizes it.
**DEV-7. Files outside the list.** `frontend/tests/utils/persona.ts` (seeding through the API) and the regenerated `routeTree.gen.ts`.
