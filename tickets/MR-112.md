## What to build
- `GET /persons/shared` → `{data: [{id, name}], count}` for the persons where the caller has a `personmember` row. Nothing else: no owner, no other names, no memory data.
- The caller's own persons are not in it (they already have `GET /persons/`); superusers get no extra rows.
- A route defined **before** `/{id}` so `shared` is not parsed as an id.

## Files
`app/models.py` (two small schemas, no table), `app/api/routes/persons.py`, `tests/api/routes/test_persons.py` (or a new `test_shared_persons.py`), regenerated `frontend/src/client/`. No migration. Stay inside these; if you need another file, ask below first.

## Notes
- Name only, because a member may talk with the persona but must not see the owner's person record (memorial-privacy rule 2, as updated in MR-107).
- Revoked members must disappear from it at once (it reads `personmember` live).

## Done when
- Every listed AC has a passing test
- A test with a second normal user (outsider sees an empty list), a superuser who is neither owner nor member (empty), an owner (own persons absent) and a revoked member (gone) (NFR-5)
- Reviewed and approved by a code owner
