## What to build
- **Member (and owner) in a chat.** An "Offer a memory" action in the chat screen opening a dialog with a text box (up to 5000 characters) that sends `POST /persons/{id}/offers` and confirms it was sent to the family.
- **Owner.** An "Offers" list on the person's page (`GET /persons/{id}/offers`), each with the text, **Accept** and **Decline**:
  - Accept calls `POST …/offers/{offer_id}/accept`, then says a new memory was created and is **not yet confirmed**, with a link to it.
  - Decline asks for a confirm, then calls `DELETE …/offers/{offer_id}`.
- Members never see the offers list.

## Files
`frontend/src/components/Offers/*` (new: `OfferMemory.tsx`, `OffersList.tsx`), the chat route from MR-110 (one mount point), the people page for the list, `frontend/tests/offers.spec.ts`. Do not hand-edit `src/client/`. Stay inside these; if you need another file, ask below first.

## Notes
- Nothing a member types in a chat becomes a memory except through an accepted offer (AC-11.4): the dialog must say the family decides.
- Offer text is private family data: no storage, no logging (NFR-8).
- After Accept, invalidate the `["memories"]` query so the new memory shows up.
