## What to build
- The Add Memory and Edit Memory forms no longer ask for a typed "Person". A memory is tied to a person only through "Link Person".
- `person_name` becomes optional when creating a memory (empty until linked). Linking a memory to a person sets `person_name` to that person's name, because the AI reads each story as "about <name>".
- The Memories table's "Person" column shows the linked person's name, or "Not linked".

## Files
`backend/app/models.py`, `backend/app/api/routes/memories.py`, `backend/app/services/processing.py`, `backend/app/services/ask_graph.py`, tests (`test_memories.py`, `test_persons.py`, `test_retrieval.py`), regenerated `frontend/src/client/`, `AddMemory.tsx`, `EditMemory.tsx`, `columns.tsx`, `PersonCell.tsx` (new), the specs that filled in the old field. No migration (the column stays; it is just allowed to be empty).

## Notes
- An unlinked memory has an empty `person_name`; extraction then uses "the person", and the Ask context leaves out "about …".
- Known gap: renaming a person does not rewrite `person_name` on memories already linked (the table reads the live name, the AI prompt text keeps the old one until the next re-extraction).
- The existing test that said linking leaves the free-text name alone is changed on purpose.

## Done when
- Backend: create without a name works, linking fills the name, blank update name is still a 422, empty name leaves "about" out of the Ask context
- Playwright: no Person field, table shows "Not linked", then the person's name after linking
- Reviewed and approved by a code owner
