## What to build
- Add Memory and Edit Memory show a **Person** select listing the owner's people, with "No person" first. Edit starts on the memory's current person.
- On save the form creates or updates the memory, then links the chosen person with the existing `PUT /memories/{id}/person` (so the backend rules for ownership and for the person name still apply). Nothing is called when the choice did not change.
- If the memory is saved but linking fails, the save stands and a toast says to use Link Person.
- The "Link Person" action stays as it was.

## Files
`frontend/src/components/Memories/PersonSelect.tsx` (new, shared), `AddMemory.tsx`, `EditMemory.tsx`, `LinkPerson.tsx` (shares the "no person" constant), `frontend/tests/memories.spec.ts`. No backend, migration or client change.

## Notes
- The list shares the `["persons"]` query with the People page.
- Creating with a person is two requests (create, then link); a failed link keeps the memory, like a failed file upload does.

## Done when
- Playwright: the select shows "No person" by default, lists people, links the chosen one on create, and on edit shows the current person and can change or clear it
- Reviewed and approved by a code owner
