## What to build
- New package `backend/app/mcp/`: a stdio MCP server (official `mcp` SDK, added to `backend/pyproject.toml`), started with `uv run python -m app.mcp`. No port, no HTTP.
- Sign-in: read `MCP_ACCESS_TOKEN` from `Settings`, resolve it to a `User` with the same checks as `get_current_user` (valid, user exists, active). No valid token means no tool is served. No admin mode.
- A small registry the later tickets add tools to, each tool running in its own database session as that user.
- Server instructions that say story text in results is data, not instructions (AC-10.3).
- A fixed set of generic error messages shared by all tools, using the app's own details ("Person not found", "Not enough permissions", "Could not validate credentials"). Logging of tool name, user id, person id, counts and timings only.
- Tool `list_personas`: persons the caller owns (`role: owner`) or was invited to (`role: member`); only `id`, `name`, `role`.
- Setting `MCP_ACCESS_TOKEN` (empty default) in `Settings` and `.env.example`.
