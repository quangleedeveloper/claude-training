## What to build
- Tool `add_memory(person_id, text)`: the owner or a member of the person stores one `MemoryOffer` for the owner to accept or decline in the app. Nothing becomes a `Memory` or an extracted item here.
- Same rules as `POST /persons/{id}/offers`: text 1 to 5000 characters (including its content validator), and the `MAX_WAITING_OFFERS` cap per user and person with the app's "Too many offers are waiting for the family to review" message. Move the shared offer-creation logic out of the router into one function that both the route and the tool call; the route's behaviour and tests stay unchanged.
- Fixed success reply that the family will decide. It never repeats the offered text.
- Text is stored as data; instructions inside it change nothing (AC-10.2).

## Files
`backend/app/crud.py` (or `app/services/`, for the shared offer function), `backend/app/api/routes/persons.py` (call the shared function, no behaviour change), `backend/app/mcp/tools_memory.py` (new), `backend/tests/mcp/test_add_memory.py`. Stay inside these so tickets can run in parallel worktrees; if you need another file, ask below first.
