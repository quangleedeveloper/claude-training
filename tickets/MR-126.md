## What to build
- One test file that runs every registered tool as an outsider, as a superuser who is neither owner nor member, and as a second normal user, and shows each is refused (AC-9.1, AC-9.3, AC-N4.1).
- A test that no tool schema has an `all_users` parameter and that an extra `all_users` argument is rejected (AC-9.2).
- A log-capture test over every tool, including failures: no line holds the question, answer, item text, memory title, offer text, token or a file path (AC-N3.1).
- Docs in `backend/README.md` (a "MCP server" section): the stdio start command with no URL or port (AC-1.2); the assistant must use a local model because the server cannot check it; where the token is stored; a leaked token reaches that user's memories until it expires, with how to rotate it (AC-N5.1); that a person with nothing confirmed gets "no memory" answers (spec concern 9).
- A test that each `MCP_*` setting is in `Settings` and `.env.example` and is mentioned in the docs.

## Files
`backend/tests/mcp/test_cross_tool.py` (new), `backend/README.md`, `.env.example` (comments only, if needed). Stay inside these so tickets can run in parallel worktrees; if you need another file, ask below first.

## Notes
- Adding a tool later should fail these tests until it is covered: build the tool list from the server's registry, not by hand.
- Use only synthetic users and memories (`tests/utils/` factories).
- No migration.
